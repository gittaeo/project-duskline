당신은 시니어 Unreal Engine 5 게임플레이 프로그래머이자 테크니컬 디자이너다. 현재 작업공간에 Unreal Engine 5 기반 3인칭 생존 액션 게임의 플레이 가능한 수직 슬라이스를 구현하라.

# 프로젝트 개요

프로젝트 가칭: Project Duskline
한국어 가칭: 황혼선

장르:

* 3인칭 싱글플레이 생존 액션
* 도심 탐색, 자원 수집, 근접 전투, 탈출이 결합된 익스트랙션 구조
* 향후 협동 또는 PvPvE 멀티플레이로 확장 가능한 구조

목표:

* 약 10분 동안 플레이할 수 있는 수직 슬라이스를 완성한다.
* 작은 폐쇄형 도심 구역 하나에서 탐색 → 루팅 → 적 조우 → 생존 → 탈출로 이어지는 게임 루프를 구현한다.
* 사실적인 그래픽 제작보다 핵심 게임플레이와 코드 구조, 안정적인 실행을 우선한다.
* Unreal Engine 기본 에셋, 단순 메시, 임시 UI를 사용해도 된다.

중요:

* 기존 게임 ‘낙원: LAST PARADISE’의 이름, 캐릭터, 스토리, 맵, UI, 로고, 아트, 사운드, 고유 설정을 복제하지 마라.
* 특정 작품의 화면이나 콘텐츠를 그대로 재현하지 마라.
* 폐허가 된 현대 도시에서 자원을 수집하고 탈출한다는 장르적 아이디어만 참고하라.
* 모든 명칭과 세계관, 코드, UI 구성은 독창적으로 작성하라.

# 기술 조건

* Unreal Engine 5 최신 설치 버전을 확인하고 현재 프로젝트 버전에 맞게 구현한다.
* 게임플레이 핵심 로직은 가능한 한 C++로 구현한다.
* 디자이너가 조정해야 하는 값은 UPROPERTY와 UFUNCTION을 이용해 Blueprint에 노출한다.
* 입력은 Enhanced Input System을 사용한다.
* 하드코딩된 액터 참조를 피하고 컴포넌트와 인터페이스 중심으로 설계한다.
* 서로 다른 시스템 사이의 결합도를 낮춘다.
* 클래스와 함수 이름은 영어로 작성한다.
* 주석은 복잡한 설계 의도와 중요한 예외 처리에만 작성한다.
* 화면에 표시되는 텍스트는 우선 한국어로 작성한다.
* 임시 에셋이 필요한 경우 Unreal 기본 도형과 기본 머티리얼을 사용한다.
* 외부 유료 에셋이나 라이선스가 불분명한 에셋을 사용하지 않는다.
* 아직 멀티플레이는 구현하지 않지만, 플레이어 상태 변경과 상호작용 로직은 향후 서버 권한 구조로 확장하기 어렵지 않게 설계한다.
* Tick 사용을 최소화하고 이벤트, 타이머, AI Perception 등의 기능을 우선 사용한다.

# 세계관

대규모 재난 이후 통신이 끊긴 가상의 도시 ‘해원시’가 배경이다. 플레이어는 격리 구역 내부로 들어가 생존 물자를 회수하는 민간 수색원이다. 제한 시간 안에 필요한 물자를 확보하고 지정된 탈출 지점으로 이동해야 한다.

도시에는 인간이었던 감염체가 남아 있다. 감염체는 시력이 좋지 않지만 소리에 민감하다. 플레이어는 전투로 돌파하거나 소음을 줄여 우회할 수 있다.

# 핵심 플레이 루프

1. 안전 구역에서 시작한다.
2. 현재 목표와 제한 시간을 확인한다.
3. 폐건물과 골목을 탐색한다.
4. 컨테이너에서 식량, 의약품, 고철 등의 자원을 수집한다.
5. 이동과 전투 과정에서 체력과 스태미나를 관리한다.
6. 발생한 소음에 따라 감염체의 관심과 추격 상태가 달라진다.
7. 목표 가치 이상의 물자를 확보한다.
8. 제한 시간이 끝나기 전에 탈출 지점에 도착한다.
9. 탈출 성공 또는 사망 결과를 표시한다.
10. 재시작할 수 있어야 한다.

# 플레이어 기능

3인칭 캐릭터에 다음 기능을 구현하라.

## 이동

* 걷기
* 달리기
* 웅크리기
* 점프
* 카메라 회전
* 달리기 중 스태미나 소모
* 스태미나가 없으면 달리기 중지
* 달리지 않을 때 일정 시간 후 스태미나 회복
* 웅크린 상태에서는 이동 속도와 소음 감소

## 상태

* 체력
* 최대 체력
* 스태미나
* 최대 스태미나
* 현재 이동 상태
* 생존, 사망, 탈출 상태
* 상태가 변경되면 UI에 즉시 반영

## 상호작용

* 플레이어 전방에 짧은 Line Trace를 사용한다.
* 상호작용 가능한 물체를 바라보면 안내 문구를 표시한다.
* 키 입력으로 아이템, 컨테이너, 탈출 지점과 상호작용한다.
* 상호작용 대상은 인터페이스로 추상화한다.

권장 인터페이스:

* IInteractableInterface
* GetInteractionText
* CanInteract
* Interact

# 전투

첫 버전에서는 근접 전투만 구현한다.

* 기본 공격
* 공격 쿨다운
* 공격 시 스태미나 소모
* 공격 범위 판정
* 적에게 피해 적용
* 피격 반응
* 플레이어 피격 및 사망
* 공격 중복 판정 방지
* 사망한 적에게 추가 피해가 적용되지 않도록 처리
* 디버그 모드에서 공격 범위 시각화 가능
* 애니메이션 에셋이 없다면 기능 검증이 가능한 임시 연출을 사용

전투 시스템을 캐릭터 클래스 하나에 모두 작성하지 말고 CombatComponent 등의 별도 컴포넌트로 분리하라.

# 감염체 AI

최소 3마리의 감염체가 맵에 존재해야 한다.

AI 상태:

* Idle
* Patrol
* Investigate
* Chase
* Attack
* Dead

행동:

* 평상시 지정된 지점을 순찰한다.
* 일정 범위 안의 플레이어를 감지하면 추격한다.
* 달리기, 공격 등의 소음 이벤트가 발생하면 해당 위치를 조사한다.
* 플레이어가 시야에서 사라지면 마지막으로 확인한 위치까지 이동한다.
* 일정 시간이 지나도 플레이어를 찾지 못하면 순찰로 복귀한다.
* 공격 거리 안에서는 플레이어를 공격한다.
* 사망하면 이동과 공격을 중지한다.

가능하면 AI Perception과 Behavior Tree를 사용하되, 프로젝트 환경이나 구현 복잡도 때문에 과도한 작업이 된다면 명확한 상태 머신으로 구현한다. 선택한 방식과 이유를 문서에 기록하라.

# 소음 시스템

플레이어 행동별로 서로 다른 크기의 소음을 발생시킨다.

예시:

* 웅크리기 이동: 매우 작음
* 걷기: 작음
* 달리기: 큼
* 근접 공격: 큼
* 컨테이너 강제 개방: 매우 큼

요구사항:

* 소음의 위치, 크기, 지속 시간을 표현할 수 있어야 한다.
* 적 AI가 소음 위치를 조사할 수 있어야 한다.
* 데이터 값은 에디터에서 조정 가능해야 한다.
* 디버그 모드에서는 소음 반경을 화면에 표시할 수 있어야 한다.
* 매 프레임 모든 AI와 거리를 비교하는 방식은 피한다.

# 아이템과 인벤토리

아이템 종류:

* 식량
* 의약품
* 고철
* 임무 물품

각 아이템 데이터:

* ID
* 표시 이름
* 설명
* 아이템 종류
* 무게
* 가치
* 최대 중첩 수
* 임시 아이콘

요구사항:

* 아이템 정의는 Data Asset 또는 Data Table로 관리한다.
* 인벤토리는 슬롯과 최대 무게 제한을 가진다.
* 동일 아이템은 최대 중첩 수까지 합칠 수 있다.
* 획득할 수 없는 경우 명확한 안내를 표시한다.
* 아이템 추가와 제거 함수는 성공 여부와 실제 처리 수량을 반환한다.
* UI에 현재 무게, 최대 무게, 아이템 목록, 총 가치를 표시한다.
* 의약품은 사용 시 체력을 회복하고 수량이 감소한다.
* 아이템이 0개가 되면 슬롯에서 제거한다.

권장 컴포넌트:

* UInventoryComponent
* UHealthComponent
* UStaminaComponent
* UCombatComponent
* UNoiseEmitterComponent

# 루팅

* 맵에 여러 개의 컨테이너를 배치한다.
* 컨테이너마다 아이템 테이블을 기준으로 내용물을 생성한다.
* 상호작용하면 루팅 UI 또는 간단한 획득 선택창을 표시한다.
* 한 번 비워진 컨테이너가 다시 무한 생성되지 않도록 한다.
* 디버깅을 위해 고정 Random Seed 옵션을 제공한다.
* 아이템 생성 결과가 없을 때도 정상적으로 처리한다.

# 목표와 탈출

* 게임 시작 시 제한 시간은 기본 10분이다.
* 최소 탈출 요구 가치가 존재한다.
* 플레이어가 요구 가치 이상을 확보한 상태에서 탈출 구역에 진입하고 상호작용하면 탈출 카운트다운을 시작한다.
* 카운트다운 중 탈출 구역을 벗어나면 취소한다.
* 탈출에 성공하면 획득한 아이템 수와 총 가치를 결과 화면에 표시한다.
* 제한 시간이 끝나거나 체력이 0이 되면 실패 처리한다.
* 결과 화면에서 게임을 다시 시작할 수 있어야 한다.

# UI

최소 UI:

* 체력 바
* 스태미나 바
* 제한 시간
* 현재 목표
* 인벤토리 무게
* 확보한 물자의 총 가치
* 상호작용 안내
* 피격 피드백
* 탈출 카운트다운
* 성공 또는 실패 결과 화면
* 재시작 버튼

UI는 기능 검증을 우선하며 과도한 시각 효과는 구현하지 않는다. UI가 게임 상태를 직접 변경하지 않도록 하고, 게임 시스템의 이벤트를 구독해 갱신하도록 한다.

# 테스트 맵

작은 테스트 맵 하나를 구성한다.

필수 구역:

* 플레이어 시작 지점
* 좁은 골목
* 실내 공간 1개
* 루팅 가능한 컨테이너 5개 이상
* 감염체 3마리 이상
* 우회 가능한 경로
* 탈출 지점
* NavMesh 영역

에셋이 부족하면 Cube, Plane, Capsule 등의 기본 도형으로 그레이박스 맵을 만든다. 코드만 생성하고 맵 구성이 자동화되지 않는다면, 에디터에서 사람이 수행해야 할 정확한 설정 절차를 문서로 작성한다.

# 안정성 요구사항

다음 예외 상황을 반드시 처리한다.

* 상호작용 대상이 도중에 제거됨
* 잘못된 아이템 데이터
* 빈 컨테이너
* 인벤토리 슬롯 부족
* 최대 무게 초과
* 체력이 최대인 상태에서 의약품 사용
* 스태미나가 부족한 상태에서 공격 또는 달리기
* 적이 추격 중 플레이어를 잃음
* 공격 대상이 공격 판정 중 제거됨
* 탈출 카운트다운 도중 플레이어가 사망함
* 제한 시간과 탈출 완료가 거의 동시에 발생함
* UI 위젯이 아직 생성되지 않은 상태에서 이벤트 발생
* 필요한 에셋이나 Blueprint가 연결되지 않은 상태

Null pointer와 잘못된 객체 참조를 방어하고, 실패 원인을 확인할 수 있는 로그를 제공한다.

# 성능 원칙

* 불필요한 Tick을 사용하지 않는다.
* 반복적인 객체 탐색을 피한다.
* 런타임 GetAllActorsOfClass 남용을 피한다.
* 컴포넌트 간 직접 참조보다 이벤트 또는 인터페이스를 우선한다.
* AI 감지는 Unreal의 감지 기능이나 이벤트 기반 구조를 사용한다.
* 디버그 출력은 개발 빌드에서 켜고 끌 수 있어야 한다.
* 향후 멀티플레이 전환 시 권한 검사를 추가할 위치를 주석 또는 문서로 남긴다.

# 구현 순서

다음 순서로 작업하라.

## Phase 0: 프로젝트 조사

1. 현재 디렉터리와 Unreal 프로젝트 파일을 확인한다.
2. 기존 코드, Blueprint, 모듈, 플러그인, 입력 설정을 분석한다.
3. 기존 사용자 변경사항을 보존한다.
4. Unreal Engine 또는 빌드 도구 사용 가능 여부를 확인한다.
5. 구현 계획과 변경 대상 파일을 간단히 정리한다.
6. 치명적인 차단 문제가 없다면 승인 질문 없이 계속 구현한다.

## Phase 2: 상호작용과 인벤토리

1. 상호작용 인터페이스
2. 아이템 데이터
3. 인벤토리
4. 루팅 컨테이너
5. 인벤토리 UI
6. 의약품 사용

## Phase 3: 전투와 AI

# 테스트 기준

가능한 범위에서 Unreal Automation Test 또는 단위 테스트를 작성한다.

필수 검증:

* 피해를 받으면 체력이 정확히 감소한다.
* 체력이 0 이하가 되면 한 번만 사망 처리된다.
* 스태미나가 부족하면 달리기와 공격이 제한된다.
* 스태미나가 최대치를 초과해 회복되지 않는다.
* 인벤토리 중첩이 최대치를 넘지 않는다.
* 무게 제한을 초과하는 아이템이 정상적으로 거절된다.
* 의약품 사용 시 체력과 수량이 정확히 변경된다.
* 빈 컨테이너 상호작용에서 오류가 발생하지 않는다.
* 사망한 AI는 플레이어를 공격하지 않는다.
* 플레이어를 잃은 AI는 일정 시간 후 순찰로 복귀한다.
* 탈출 조건을 충족하지 않으면 탈출할 수 없다.
* 탈출 구역을 벗어나면 카운트다운이 취소된다.
* 사망과 제한 시간 종료가 동시에 발생해도 결과가 중복 처리되지 않는다.
* 게임 재시작 후 이전 실행의 상태가 남지 않는다.

# 완료 조건

다음 조건을 충족해야 수직 슬라이스가 완료된 것으로 판단한다.

* 프로젝트가 컴파일된다.
* 에디터에서 테스트 맵을 실행할 수 있다.
* 플레이어가 이동, 달리기, 웅크리기, 상호작용, 공격을 수행할 수 있다.
* 최소 5개의 컨테이너에서 아이템을 획득할 수 있다.
* 인벤토리의 수량, 무게, 가치가 정상적으로 계산된다.
* 최소 3마리의 AI가 순찰, 조사, 추격, 공격, 사망 상태를 수행한다.
* 플레이어 행동이 소음을 발생시키고 AI가 반응한다.
* 요구 가치 확보 후 탈출할 수 있다.
* 사망, 시간 초과, 탈출 성공 결과가 각각 표시된다.
* 게임을 재시작할 수 있다.
* 주요 예외 조건에서 크래시가 발생하지 않는다.
* 구현 방법과 에디터 설정 방법이 문서화돼 있다.

# Codex 작업 규칙

* 먼저 저장소를 조사한 뒤 실제 파일을 수정하라.
* 기존 파일과 사용자 변경사항을 임의로 삭제하거나 되돌리지 마라.
* 존재하지 않는 API나 클래스를 추측해 사용하지 마라.
* 현재 Unreal 버전에서 사용할 수 있는 API인지 확인하라.
* 컴파일하지 못했다면 성공했다고 보고하지 마라.
* Unreal Engine이 설치되지 않아 빌드할 수 없다면 코드 정적 검사를 수행하고, 미검증 항목과 실행에 필요한 명령을 정확히 기록하라.
* Blueprint나 에디터 수동 작업이 필요하면 생략하지 말고 단계별 체크리스트를 작성하라.
* 과도한 시스템을 한 클래스에 몰아넣지 마라.
* 현재 수직 슬라이스에 필요하지 않은 제작, 스킬 트리, 온라인 매칭, 상점, 현금 결제, 대규모 오픈월드는 구현하지 마라.
* 문제가 발생하면 임시로 기능을 삭제하기보다 원인을 분석하고 최소 수정으로 해결하라.
* 플레이 가능한 결과를 우선하고 조기 추상화를 피하라.
* 외부 라이브러리를 추가해야 한다면 먼저 필요성과 라이선스를 확인하라.
* 작업 중 합리적인 세부 결정은 스스로 내리고 진행하되, 프로젝트를 파괴할 위험이 있거나 필수 정보가 없을 때만 질문하라.
